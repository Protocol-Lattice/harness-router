Architecture

Make the discrete choice small.

harness-router is deliberately not another agent framework. It is a narrow selection layer between compact harness state and a fixed tool registry.

01

Goal + observation

Your harness builds compact state instead of replaying an entire conversation.

02

Candidate tools

Generic or MCP tools become normalized descriptors with category and risk metadata.

03

Jev chooses

Jev selects the discrete next action and returns confidence plus probabilities.

04

Escalate intelligently

Ambiguous choices can enter bounded MCTS search or fall back to the main planner.

05

Your executor runs

Authorization and execution remain separate. Confidence is never permission.

Native MCP for Codex

Install the router once. Keep the skill tiny.

The native stdio MCP server exposes fast route plus bounded route_mcts. Codex should use them only at real ambiguity points, while obvious read → edit → test steps stay on the normal fast path. The MCP implementation currently lives on main, so install it directly from GitHub until the next package release.

01 · INSTALL

Install globally with uv

Install the latest harness-router plus the optional MCP SDK into an isolated global tool environment. 

uv tool install --force \
  --with 'mcp>=2,<3' \
  'git+https://github.com/Protocol-Lattice/harness-router.git@main'

uv tool update-shell
02 · KEY

Expose the OpenRouter key

The MCP server starts without the key, but route needs it when a Jev decision is requested. 

export OPENROUTER_API_KEY="..."

command -v harness-router-mcp

Never put the key value in prompts, tool descriptions, routing state, source files, or Git.

03 · CODEX

Register the stdio server

Add the executable to Codex, then verify that the server is configured. 

codex mcp add harness-router -- harness-router-mcp

codex mcp list
Codex config

Pass the key by name, not by value.

In ~/.codex/config.toml, allow Codex to forward OPENROUTER_API_KEY to the local stdio process. If Codex cannot resolve harness-router-mcp through PATH, replace the command with the absolute path returned by command -v harness-router-mcp. 

[mcp_servers.harness-router]
command = "harness-router-mcp"
env_vars = ["OPENROUTER_API_KEY"]
enabled = true
startup_timeout_sec = 10
tool_timeout_sec = 5
MCP MCTS

Look ahead without executing real tools.

Use route_mcts only when the best first action depends on downstream consequences and your harness can provide a predicted, side-effect-free state graph. The search executes no real writes, shell commands, browser mutations, or network mutations. 

route           # fast Jev decision
route_mcts      # bounded PUCT search

recommended:
simulations = 32
max_depth = 3
use_jev_prior = true

# Jev is evaluated at most once.
# Remaining simulations are local.
Verify it

Restart Codex after changing the MCP configuration, then run /mcp. The harness-router server should expose both route and route_mcts. Running harness-router-mcp manually should appear to hang silently — that is normal: the stdio server is waiting for an MCP client. If the API key is missing, the server still loads and route returns a controlled missing_openrouter_api_key fallback.

Experimental search strategy

When one choice is not enough, search the next few.

Jev is strongest as a fast System-1 selector. For ambiguous states, use it to seed a small Monte Carlo Tree Search instead of asking the main model to repeatedly reconsider the entire tool registry. Search a bounded action tree, choose the best first move, execute exactly one tool, then re-plan from fresh state.

Jev-seeded MCTS

Keep the tree narrow and cheap. Candidate actions come from Jev probabilities; rollouts evaluate short tool sequences against progress, verification, cost, and risk.

01
Seed top-k actions Use Jev probabilities as priors instead of expanding every available tool.
02
Select + expand Use UCB/PUCT to balance high-value branches with under-explored alternatives.
03
Run bounded rollouts Search only a few actions deep. Prefer dry-run state transitions when tools mutate state.
04
Backpropagate reward Score goal progress and verification positively; subtract latency, tokens, risk, and failed actions.
05
Execute one action Commit only the best root action, observe the real result, discard the stale tree, and search again.

Search a tiny horizon.

The goal is not exhaustive planning. It is a bounded second opinion for states where a single routing decision has low confidence or several plausible continuations.

Decision policy

Fast path first. Search only on uncertainty.

A practical trigger is confidence below your routing threshold, a small margin between the top two actions, or a high-impact decision. MCTS should be an escalation path, not the default for every tool call. 

async def choose_next_action(state, tools):
    ranked = await jev.rank(state, tools)

    if ranked.confidence >= FAST_PATH_THRESHOLD:
        return ranked.best

    root = Node(state, priors=ranked.top_k(4))

    for _ in range(32):
        leaf = select_with_puct(root)
        child = expand_one(leaf)

        reward = await rollout(
            child,
            depth=3,
            reward=lambda r: (
                2.0 * r.verified_progress
                - 0.4 * r.cost
                - 1.2 * r.risk
                - 1.0 * r.failure
            ),
        )
        backpropagate(child, reward)

    return root.best_child().action
    # execute ONE real action, observe, then rebuild
Python API

Or embed it directly in your harness.

Use hybrid mode as the default. Route bounded choices with Jev, then let your planner handle code, patches, shell arguments, and open-ended reasoning.

Install in one line.

Set OPENROUTER_API_KEY. The default provider uses typesafe/jev-1.13 through the OpenRouter Decisions API.

Full docs 
from harness_router import (
    HarnessState,
    JevToolRouter,
    OpenRouterConfig,
    OpenRouterJevProvider,
    RoutingConfig,
)

provider = OpenRouterJevProvider.from_config(
    OpenRouterConfig()
)
router = JevToolRouter(provider, RoutingConfig())

decision = await router.route(
    HarnessState(
        goal="Fix the failing parser test",
        observation="Failure points to src/parser.py",
    ),
    tools,
)

if decision.fallback:
    # hand the choice back to your planner
    ...
else:
    print(decision.tool, decision.confidence)
The rule

Do not optimize the router. Optimize the whole loop.

harness-router is alpha software. The measured Codex skill integration shows exactly why end-to-end evidence matters: a fast selector can still make the complete agent slower or more expensive when the surrounding integration adds turns and fallbacks.
