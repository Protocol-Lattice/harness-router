Why Jev?

≈42×

cheaper than GPT-5.3-Codex Input-token price · $0.042/MTok vs $1.75/MTok

In harness-router’s 24 paired route decisions, the Jev-powered router chose the same tool as Codex in 24/24 cases while median decision latency was 332 ms vs 3,384 ms for Codex — 10.2× faster in that run.

On published input-token rates, Jev is about 41.7× cheaper than GPT-5.3-Codex: $0.042 per million input tokens versus $1.75. Jev output tokens are free, so the total request-cost gap can be larger depending on how much output Codex generates.

The point is not to replace Codex’s planner. Jev handles the narrow, closed-choice routing step; Codex keeps the broader reasoning and execution loop.

When one move is not enough, search.

route_mcts explores a supplied side-effect-free state graph. Jev can seed the root once; the remaining simulations are local. The server never executes simulated writes, shell commands, browser mutations, or network mutations. It selects only the first real action.

Methodology & source data

What the clocks include

Codex chose a name only; its timer includes response generation, host scheduling, and dispatch. Router timings include MCP transport and the provider round trip; MCTS also includes local search. Graph preparation is excluded. Pure reasoning time and task completion time were not measured.

How to read the results

These exploratory runs used different workloads in an existing Codex conversation, with cases authored by Codex. They do not isolate the cost of MCTS over ordinary routing. Matching choices measure agreement; the MCTS test checks the highest-reward branch. No Python scripts or OpenAI API calls were used.

$ 06 · Codex Hook Flow

Discover once. Route every call.

On a fresh Codex startup, Harness Router discovers the MCP inventory immediately, writes the full tool catalog, then reuses that catalog for every PreToolUse decision.

01 · COPY HOOK

Add the project hook

Copy the hook config plus both Python scripts into the repository where Codex runs.

mkdir -p .codex/hooks curl -fsSL https://raw.githubusercontent.com/Protocol-Lattice/harness-router/main/.codex/hooks.json \ -o .codex/hooks.json curl -fsSL https://raw.githubusercontent.com/Protocol-Lattice/harness-router/main/.codex/hooks/discover_tools.py \ -o .codex/hooks/discover_tools.py curl -fsSL https://raw.githubusercontent.com/Protocol-Lattice/harness-router/main/.codex/hooks/pre_tool_use.py \ -o .codex/hooks/pre_tool_use.py
02 · START

Start a fresh Codex session

SessionStart runs only for startup. It queries codex app-server via mcpServerStatus/list and writes the complete catalog before the model starts using tools.

.codex/harness-router-tools.json .codex/harness-router/sessions/<session_id>.json
Behavior

Fail open. Keep approvals.

Each PreToolUse call uses fast route first. When that decision is uncertain and a side-effect-free graph provider is configured, the hook can escalate to route_mcts. Without a graph provider it never invents an MCTS tree. Same choice, fallback, timeout, or router error lets the original call continue. A different confident choice blocks only that call and asks Codex to re-plan once. Sandbox and approval rules remain untouched.

$ 07 · Install

Three steps. Then get out of the way.

Install the latest main branch, expose your OpenRouter key to the local MCP process, and register the server in Codex.

01 · GLOBAL

Install

Keep it isolated and globally available through uv tool.

uv tool install --force \ --with 'mcp>=2,<3' \ 'git+https://github.com/Protocol-Lattice/harness-router.git@main'
02 · ENV

Expose the key

The server can load without it. Jev routing needs it when route is called.

export OPENROUTER_API_KEY="..." command -v harness-router-mcp
03 · CODEX

Register MCP

Add the stdio server, restart Codex, then verify both tools with /mcp.

codex mcp add harness-router -- \ harness-router-mcp codex mcp list
$ 08 · The rule

One router. Two ways in.
Skill or hook.

Use the skill when you want explicit control. Use the hook when you want every tool call checked automatically. Harness Router keeps simple decisions fast and brings in route_mcts only when the choice needs deeper search.
